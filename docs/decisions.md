- 2026-11-19: Two changes to how counts are computed, both still tested on made-up sentences only and not run on any post text or data (G1 is still unsigned). (1) The matcher now matches each category independently over the full text, longest-first only within a category. Before, a long phrase in one category claimed its words and silently lowered another category's count ("never give up" in A took "never" from B), which would have made category counts depend on how long the other dictionaries' phrases are. Spans of different categories can now sit on the same words, so the matcher also returns a cross-category span-overlap report (per pair of categories, how many matched spans of each sit inside or overlap a span of the other) beside the existing report of identical entries listed under two categories. Both reports are for a human to read; the code never resolves them and no count changes because of them. (2) The voice counter no longer counts the all-caps token "US" as first-person plural, because it is almost always the country. "us" and "Us" still count, and "US" is still one word in the total, so the share's denominator is unchanged. Remaining blind spot: a sentence written in capitals loses its real plural "US". The earlier statements that longest-first held across categories and that "US" counted as "us" are superseded.

## 2026-11-09: conservative cell-level dedupe replaces the looser key (step 2)

candidate groups (see Findings above: most content-different groups are neither a prefix nor a trailing-number

group still holds more than one kept row). Real post-level deduplication happens after segmentation, not here.

## 2026-11-09: segmenter counts a repost or embedded post as one post by the leader (step 5)

- Rule (a construct decision the course mentors and the human check can still overturn): a repost or embedded post is **one post by the leader**, never a second post. Given the leader's name key, a header whose name line is not the leader's is embedded in the current post; a header by the leader opens a new post. A cell with no header by the leader is one post with an empty leader voice.
- New fields: `is_repost` (per post, and per cell), and `embedded_text`, which keeps the embedded post out of the leader-voice `text`. "<name> reposted this" notice lines set `is_repost` and are dropped from the leader voice. The raw cell is never touched.
- Name match: the header's name tokens and the leader's name tokens must be contained one in the other, so "Dr." or "CFA" does not break a match. Two people sharing the same tokens would be taken for the leader; this is not measured.
- Not done on purpose: the segmenter was **not run on all cells**, and the sample was **not scored**. The match rate between feed names and the leader column is therefore unmeasured. A header the leader wrote under a different spelling would be treated as embedded, so the count would be too low for that cell. The human check of the 200 cells is where this shows up.
- `src.segment_score` now passes the leader key too, so a later G1 score uses the same rule as the segmenter. It was not run.
